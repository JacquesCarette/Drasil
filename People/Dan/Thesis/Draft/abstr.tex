\prefacesection{Abstract}

Scientific software is represented by more than executable code. Requirements
specifications, design documents, source code, and build instructions present
overlapping knowledge to different audiences. Repetition across these artifacts
is often necessary; the maintenance problem arises when each occurrence is
independently editable and can therefore become inconsistent, incomplete, or
untraceable. This thesis investigates whether explicitly capturing shared
knowledge and generating its artifact-specific presentations can reduce that
burden.

Drawing on six \mbox{\emph{input~$\rightarrow$~process~$\rightarrow$~output}}
scientific-computing case studies, the work analyzes requirements, design, and
implementation artifacts to identify recurring structures, common domain
knowledge, and system-specific variation.
These observations inform Drasil, an extensible knowledge-centric framework
implemented as lightweight domain-specific languages embedded in Haskell.
Drasil represents concepts, definitions, symbols, units, equations, their
relationships, and more as reusable chunks. Recipes select and organize those 
chunks for particular artifacts and audiences; deterministic generators render 
the resulting structures as requirements specifications, executable source code 
in multiple languages, and supporting files such as build instructions.

Implementing the six case studies in Drasil provides observational evidence that
this architecture produces consistency by construction, explicit provenance,
and deterministic regeneration. Knowledge-level edits propagated across
generated documentation and code, while explicit encoding exposed missing
definitions, inconsistent symbols, implicit unit conversions, and undocumented
assumptions in the original artifacts. Reuse of shared knowledge for two related
systems also demonstrated how targeted changes can produce software-family
variants without duplicating their common content. These results are not a
controlled measurement of productivity or defect reduction: Drasil requires
substantial up-front modelling, imposes a nontrivial onboarding cost, and
currently works best for well-understood scientific software of the kind
considered here. Within that scope, the thesis demonstrates the feasibility of
replacing separately maintained representations with explicit knowledge and
generated projections, and identifies authoring support, broader knowledge
representation, and controlled empirical validation as priorities for future
work.
